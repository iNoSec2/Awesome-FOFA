# 网络空间测绘平台 Benchmark V1 评测标准

---

**文档编号：** BenchMark-NCM-V1

**版本号：** V1

**发布日期：** 2026年8月

**评测对象：** 网络空间测绘平台

---

## 前言

网络空间测绘是识别、采集和持续跟踪全球网络资产及其服务状态的过程。随着网络空间资产规模持续扩大，测绘平台的能力差异直接影响安全感知、威胁狩猎和资产暴露面管理的覆盖范围与时效性。

本标准建立网络空间测绘平台的评价指标体系和计分方法，适用于任何符合条件的网络空间测绘平台。

## 1 范围

本标准适用于网络空间测绘平台的能力评测，评测以下四类能力：

1. 数据采集能力；
2. 数据新鲜度；
3. 搜索与获取性能；
4. DNS发现能力。

## 2 术语和定义

### 2.1 唯一网络服务资产

唯一网络服务资产的键是：

```text
IP + 端口 + 应用协议
```

### 2.2 应用协议

应用协议指 HTTP、HTTPS、SSH、RDP、MySQL 等平台实际识别出的服务协议。

### 2.3 应用协议归一化

评分前必须冻结应用协议归一化对照表。

各参评平台的协议名称先映射到同一份归一化对照表，再进行去重和评分。同义名称、简称与全称、同一协议的版本名称，以及仅因 TCP/UDP 探测方式产生的名称差异，应合并为同一个规范协议。

不同协议族、不同管理接口及具有独立服务语义的协议应分别保留。平台自行识别的厂商专属协议或扩展协议，只要指向明确、可验证的服务协议，不因未被公共协议库收录而排除。

存在语义歧义且无法确认的协议名称，在归一化对照表冻结前不得进入正式计分。对照表在开测前冻结并在评测报告中公布。

### 2.4 FQDN

FQDN（Fully Qualified Domain Name，完全合格域名）。在本标准中，FQDN 规范化包括转为小写、去除末尾点号。

### 2.5 泛解析

泛解析指通过 DNS 通配符记录使大量不存在的子域名解析到相同 IP 的现象。本标准通过统一的规则识别并折叠泛解析记录，清理规则和被折叠的记录在评测报告中公布。

### 2.6 有效子域名

有效子域名必须同时满足：

1. FQDN 规范化和去重后唯一；
2. 测试时能够解析到公网 IP；
3. 通过统一的泛解析识别与折叠规则。

### 2.7 标准字段清单

标准字段清单以公开协议规范和可验证的字段含义为依据，不直接采用任何一家平台的私有字段名。不同平台含义相同的字段统一映射到同一标准字段，字段映射表与标准字段清单同时在开测前冻结。

### 2.8 评测方

评测方指依据本标准执行测试、采集证据并出具评测报告的组织或个人。

## 3 评测指标体系与评分方法

### 3.1 能力分类

本标准设置四个能力大类，用于组织测试任务和结果表。各结果表独立计分。

| 能力大类    | 二级类别                                      |
| ------- | ----------------------------------------- |
| 数据采集能力  | 近 30 天数据规模、协议覆盖广度、有效独有协议、协议深度识别采样、样本覆盖与识别 |
| 数据新鲜度   | 数据新鲜度                                     |
| 搜索与获取性能 | 页面查询性能、API 单次查询性能、API 连续翻页性能              |
| DNS发现能力 | DNS发现能力                                   |

### 3.2 计分通则

所有独立评分结果均按对应章节定义换算为 0—100 分。不同结果表可能使用不同的测试对象、分母、单位、满分含义和失败条件，分数只用于该表内部的平台横向比较。

各结果表须标注计分口径、原始值、分母或分档、时间范围和样本范围。不同口径下的 100 分含义如下：

| 计分口径 | 适用结果                  | 100 分的含义                |
| ---- | --------------------- | ----------------------- |
| 固定基准 | 近 30 天数据规模            | 达到或超过 10 亿唯一网络服务资产      |
| 参考覆盖 | 协议覆盖广度、有效独有协议、DNS发现能力 | 覆盖该项公式定义的全部参考分母         |
| 固定分档 | 数据新鲜度、搜索与获取性能         | 所有计分样本或任务均落入最高分档        |
| 样本加权 | 样本覆盖与识别               | 资产、端口和应用协议三项样本覆盖均达到满分   |
| 字段加权 | 协议深度识别采样              | 在有效共同目标上取得预定义的全部高价值字段分值 |

具体公式均在对应章节定义，不因参评平台的当轮名次调整阈值、分母或权重。

- 平台缺少某项能力，该项记 0 分，并标注不支持。
- 评测方执行失败或证据缺失，该项重测。
- 因平台功能、账号权益、分页或导出限制无法完成某项测试时，按对应章节规定记 0 或标记"不支持"。
- 因评测环境故障或证据未交付导致无法评测时，标记"待补测"，不得以 0 分代替，也不得发布该表排名。

### 3.3 结果报告要求

评测报告须发布以下独立得分：

1. 近 30 天数据规模得分
2. 协议覆盖广度得分
3. 有效独有协议得分
4. 协议深度识别采样得分
5. 样本覆盖与识别得分
6. 数据新鲜度得分
7. 页面查询性能得分
8. API 单次查询性能得分
9. API 连续翻页性能得分
10. DNS发现能力得分

## 4 测试条件

### 4.1 账号要求

使用评测当日各平台官网可直接购买的个人用户最高档账号。本标准评价公开可购买账号实际可使用、可验证的产品能力，不评价平台未向该账号开放的内部数据或企业专属能力。

### 4.2 唯一资产定义

唯一网络服务资产以 `IP + 端口 + 应用协议` 为键（定义见 2.1）。各参评平台的协议名称先映射到同一份应用协议归一化对照表（定义见 2.3），再进行去重和评分。同义名称合并计算，对照表在开测前冻结并在评测报告中公布。

### 4.3 测试环境

各参评平台在同一轮测试中完成。测试地点、网络、超时时间和重试次数保持一致。执行顺序随机。

## 5 数据采集能力评测

数据采集能力包含五项独立结果。

### 5.1 评分项

| 独立结果         |  满分 | 回答的问题                     |
| ------------ | --: | ------------------------- |
| 近 30 天数据规模得分 | 100 | 平台近 30 天内有多少唯一网络服务资产？     |
| 协议覆盖广度得分     | 100 | 平台对规范应用协议集合的覆盖质量如何？       |
| 有效独有协议得分     | 100 | 平台发现了多少经验证且其他参评平台未检出的协议？  |
| 协议深度识别采样得分   | 100 | 平台识别协议后，能够取得多少具有价值的字段？    |
| 样本覆盖与识别得分    | 100 | 平台对统一混合样本的资产、端口和协议覆盖表现如何？ |

### 5.2 近 30 天硬指标

唯一资产数量、协议覆盖广度和有效独有协议所使用的底层检出数据，均统一统计评测基准日前连续 30 天内的数据。各参评平台必须披露实际查询条件、时间起止点与时区；无法设置时间范围的平台，须披露其返回数据的实际时间含义和可比性限制。

三项硬指标使用同一近 30 天时间范围。计算口径：

- 唯一资产数量：按 `IP+端口+应用协议` 去重。
- 应用协议覆盖广度：按应用协议归一化对照表归并后，对每个规范协议以递减收益函数 `ln(1+n)` 计算检出质量，平台各协议质量之和与全平台各协议最高质量之和的比值计分。
- 有效独有检出协议：经归一化对照表归并后，仅一个参评平台检出有效资产的规范协议。无最低资产量门槛，1 条有效资产即计入。

#### 5.2.1 近 30 天唯一资产数量

唯一资产数量采用 **10 亿** 个唯一网络服务资产作为基准分母，该基准参考量级设定。

```text
近 30 天唯一资产数量得分
= min（平台近 30 天唯一资产数量 ÷ 1,000,000,000 × 100，100）
```

#### 5.2.2 协议覆盖广度

设：

- P 为全部参评平台集合；
- C 为归一化后的规范应用协议集合；
- n(p,i) 为平台 p 对规范协议 i 检出的有效唯一资产数量；
- 唯一资产按 `IP+端口+规范应用协议` 去重；
- 单协议检出质量采用递减收益函数：

```text
q(p,i) = ln(1 + n(p,i))
```

该函数不设置最低资产量门槛：即使协议只有 1 条有效资产也会获得较小权重，随着资产量增加边际收益逐渐下降。

对每个规范协议，取全部参评平台中的最高检出质量：

```text
m(i) = max(q(p,i))，对所有 p ∈ P
```

平台协议覆盖质量：

```text
B(p) = Σ q(p,i)，对所有 i ∈ C
```

联合协议覆盖质量：

```text
B_ref = Σ m(i)，对所有 i ∈ C
```

平台协议覆盖广度得分：

```text
协议覆盖广度得分 = 100 × B(p) ÷ B_ref
```

当 B_ref = 0 时，所有平台本项得分为 0。

#### 5.2.3 有效独有协议

若规范协议 i 只有平台 p 检出有效资产，则该协议属于平台 p 的有效独有检出协议。

定义独有检出指示量：

```text
I(p,i) = 1，当 n(p,i) > 0 且对所有 r ≠ p，n(r,i) = 0
I(p,i) = 0，其他情况
```

平台独有检出质量：

```text
U(p) = Σ I(p,i) × q(p,i)，对所有 i ∈ C
```

全部参评平台的独有检出质量分母：

```text
U_ref = Σ U(p)，对所有 p ∈ P
```

平台有效独有检出协议得分：

```text
有效独有协议得分 = 100 × U(p) ÷ U_ref
```

当 U_ref = 0 时，所有平台本项得分为 0。若全部有效独有协议均属于同一个平台，则该平台本项获得 100 分。

另一平台即使仅检出 1 条有效资产，该协议便不再属于独有检出协议。

### 5.3 协议深度识别采样

本项评估参评平台在识别出同一应用协议后，进一步获取协议字段信息的能力。资产发现和协议识别由本章其他结果评分，本项不重复计分。

本项称为"采样评测"是因为在三个层面采用代表性样本而非全量普查：协议层面选取 10 种典型非 Web 协议，不代表全部应用协议；目标层面使用各参评平台的共同目标（即各平台实际检出目标的交集），不代表该协议的全部资产；字段层面使用预定义的高价值字段集合，不代表协议的全部字段。采样范围在开测前冻结。

#### 5.3.1 样本

本项评测 10 种应用协议，覆盖三类典型非 Web 服务：

| 类别         | 协议                  |
| ---------- | ------------------- |
| 远程访问       | RDP、SSH、Telnet      |
| 数据库与中间件    | MySQL、MongoDB、Redis |
| 邮件、网管与 IoT | FTP、SMTP、SNMP、MQTT  |

每种协议使用各参评平台的共同目标进行评分。共同目标按 `协议+IP+端口` 匹配，各平台须返回可评审的协议响应，且实际服务与待测协议一致。

抽样流程：

1. 按 10 种待测协议分别生成候选目标，保留目标 IP、端口、传输层、协议标签和观测时间。
2. 独立验证服务真实存活，且各平台返回内容属于同一目标协议。
3. 只保留各参评平台均有可评审响应的共同目标；任一平台响应不可用时，该目标从该协议所有平台的平均分计算中剔除。
4. 同一目标存在多条记录时，按观测时间最接近原则选取。
5. 10 种协议等权平均。

#### 5.3.2 字段权重与取得系数

每种协议独立 100 分，按各字段对资产测绘、漏洞发现和暴露面管理的贡献程度分配分值。完整字段目录及权重在评测报告中公布。

##### 取得系数

| 取得系数 | 判定条件                           |
| ---: | ------------------------------ |
|  1.0 | 结构化或可读协议文本                         |
|  0.5 | 可解码但未解析的二进制、可按固定算法复算的确定性派生字段 |
|    0 | 无有效值或无法复算的主观推断                    |

同一语义的直接值、格式化值和派生值只取一次，不重复累计。

##### 高价值字段

高价值字段指对安全资产测绘有直接贡献的协议字段，按用途分为：

- 资产身份与唯一标识（如主机密钥指纹、设备型号）
- 产品与版本信息（如服务端软件版本、固件版本）
- 安全配置与暴露状态（如认证状态、匿名访问、TLS 参数）
- 设备角色与功能能力（如节点角色、支持方法、功能码）

字段分值按上述贡献程度集中分配，允许少数关键字段占据较高分值。分值不按任何参评平台的返回率或采集难度设定。

##### 计分公式

```text
单目标分 = Σ（字段分值 × 字段取得系数）
```

每种协议字段分值合计 100，单目标满分 100。缺失字段的分值不向其他字段重分配。

```text
某协议深度识别得分 = 该协议有效共同目标的单目标分之和 ÷ 该协议有效共同目标数量
```

平台仅返回协议名称、端口或通用资产标签，未提供任何字段所需有效协议内容时，该目标得 0 分。

#### 5.3.3 汇总计分

```text
协议深度识别采样得分 = 本轮可评协议深度识别得分之和 ÷ 本轮可评协议数量
```

本轮可评协议数量小于 10 时，仅对有有效共同目标的协议等权平均。无有效共同目标的协议记为 N/A，不参与平均。

### 5.4 混合样本

混合样本以 `IP+端口+应用协议` 为唯一计数。评测方从各参评平台的默认范围结果中各抽取 50 条候选资产，样本须覆盖不同地区、不同应用协议，并优先覆盖不同端口和不同网段。

候选资产在开测前必须独立验证为真实存活服务，并确认实际应用协议。

正式样本是各参评平台候选结果的并集。正式样本目标数量为参评平台数 × 50。合并去重后不足该数量时，按各来源等量补充候选至达标；超过该数量时不截断。平台每命中一条计一条，未命中记 0。

### 5.5 混合样本计分

**资产覆盖率**

```text
混合样本资产覆盖率得分
= 平台正确命中的唯一资产数
÷ 正式样本数量
× 100
```

必须同时匹配 IP、端口和应用协议。

**端口覆盖率**

先对样本中每个端口分别计算资产命中率，再对所有样本端口取平均。每个端口权重相同，避免 80、443 等常见端口主导结果。

```text
某端口命中率
= 平台命中的该端口样本数
÷ 正式样本中该端口的样本总数
× 100
```

```text
混合样本端口覆盖率得分
= 全部样本端口命中率之和
÷ 正式样本中的唯一端口数量
```

**应用协议识别率**

先对样本中每种应用协议分别计算正确识别率，再对所有样本协议取平均。每种协议权重相同。

```text
某应用协议识别率
= 平台正确识别该协议的样本数
÷ 正式样本中该协议的样本总数
× 100
```

```text
混合样本应用协议识别率得分
= 全部应用协议识别率之和
÷ 正式样本中的应用协议种类数
```

**样本覆盖与识别得分**

三项指标按 40%:30%:30% 的权重计算：

```text
样本覆盖与识别得分
= 混合样本资产覆盖率得分 × 40%
+ 混合样本端口覆盖率得分 × 30%
+ 混合样本应用协议识别率得分 × 30%
```

### 5.6 结果展示

本章发布五项独立得分。

## 6 数据新鲜度评测

本章使用各参评平台的样本并集，比较平台对这些资产的覆盖情况和最后更新时间。平台未收录某条样本时，该条样本得 0 分。

### 6.1 样本

本章使用与第 5 章相同的正式样本并集（样本构成与抽样规则见 5.4）。正式样本整体须覆盖不同网段、不同端口和不同应用协议，不得集中在少数网段、常见端口或单一协议。

### 6.2 计分方法

每条样本使用各平台对外返回的最后更新时间。平台未命中该资产、时间字段缺失或时间字段含义无法确认时，该条样本得 0 分。

每条样本按最后更新时间距离测试时间的天数计分：

| 最后更新时间        | 单条得分 |
| ------------- | ---: |
| 近 7 天         |  100 |
| 8—30 天        |   80 |
| 31—90 天       |   50 |
| 91—365 天      |   20 |
| 超过 365 天      |    0 |
| 时间字段缺失或含义无法确认 |    0 |

```text
数据新鲜度得分
= 全部正式样本得分之和
÷ 正式样本数量
```

## 7 搜索与获取性能评测

本章评测各参评平台在页面搜索和 API 调用场景下的响应性能。

### 7.1 评分项

| 独立结果       |  满分 | 测试方法                          |
| ---------- | --: | ----------------------------- |
| 页面查询性能     | 100 | 含四项子分，各占 25%，见下表              |
| API 单次查询性能 | 100 | 50 次固定 API 请求                 |
| API 连续翻页性能 | 100 | 按 1 秒一页连续获取 50 页并计算单页响应时间 P95 |

页面查询性能由以下四项子分组成，各占 25%：

| 子项   |  权重 | 测试方法                      |
| ---- | --: | ------------------------- |
| 全文检索 | 25% | 40 个固定页面任务                |
| 简单查询 | 25% | 40 个单字段精确或过滤页面任务          |
| 复杂查询 | 25% | 40 个 AND、OR、NOT 及括号组合页面任务 |
| 极限查询 | 25% | 10 个模糊、正则或多层嵌套页面任务        |

执行规则：

- 网页查询从提交查询到完整返回结果计时。API 从发出请求到完整接收响应计时。
- 页面与 API 单次任务超时、报错、缺少对应语法或执行了不等价查询，该任务记 0 分。
- 连续翻页以完成 50 页为达标条件，中断或达到平台上限记 0 分。
- 每个任务先独立计分，再计算该类任务的平均分。页面查询性能的四项子分按 25% 等权合成。
- 因评测方未采集或证据未交付导致缺项时，该项补测完成前不发布对应结果表排名。

### 7.3 计分方法


```text

= 该类全部任务得分之和
÷ 该类任务总数
```

```text

```

## 8 DNS发现能力评测

评测方独立提供 150 个固定主域名作为测试入口。主域名从公开知名组织中选取，包括上市企业、大型互联网服务。

各参评平台查询相同的 150 个主域名。每个平台应导出这 150 个主域名对应的完整子域名结果，合并后形成该平台的候选子域名集合，再统一计算得分。

有效子域名必须同时满足：

1. FQDN 规范化和去重后唯一；
2. 测试时能够解析到公网 IP；
3. 通过统一的泛解析识别与折叠规则。

同一子域名存在多个 IP、端口或服务时，有效子域名数量只计算一次。

域名端口覆盖数量和关联唯一 IP 数量独立计算，不依赖有效子域名集合：只要记录存在于平台完整返回结果中并通过格式规范化与去重，即可进入对应指标。

### 8.1 评分项

| 指标         |  权重 | 计算方法                                   |
| ---------- | --: | -------------------------------------- |
| 有效子域名数量    | 40% | 完整候选结果规范化、去重并完成有效性与泛解析清理后保留的唯一 FQDN 数量 |
| 域名端口覆盖数量   | 25% | 平台完整返回结果中规范化、去重后的唯一 `FQDN+端口` 数量       |
| 关联唯一 IP 数量 | 15% | 平台完整返回结果中规范化、去重后的唯一公网 IP 数量            |
| 独有有效子域名数量  | 20% | 仅该平台发现、其他完成本项测试的平台均未发现的有效子域名数量         |

固定主域名样本中，候选子域名数量按以下顺序计算：

1. 取得平台对 150 个主域名返回的完整结果；
2. 将 FQDN 转为小写、去除末尾点号并过滤不属于固定主域名的记录；
3. 按 FQDN 去重，形成候选子域名集合；
4. 再进行公网解析验证和统一的泛解析识别与折叠，形成有效子域名集合。

域名端口覆盖数量使用第 2 步规范化后的完整结果，按 `FQDN+端口` 去重；关联唯一 IP 数量使用同一完整结果中的公网 IP，排除内网、保留地址和格式无效的 IP 后去重。两项的计算范围均为平台完整返回结果，不先按有效子域名集合筛选。

查询语法、结果对象含义、有效性规则、泛解析规则以及域名、端口和 IP 的规范化方法均在开测前冻结。

四项的分母均取各参评平台该指标的并集去重总数（独有有效子域名为简单求和），而非单一平台的最高值。除非某平台独立覆盖了全部子域名、端口或 IP，否则不会出现满分。得分反映各平台对样本域名资产空间的覆盖比例。

### 8.2 计分方法

四项分别计算：

```text
有效子域名数量得分
= 平台有效子域名数量
÷ 各参评平台有效子域名并集去重后的总数
× 100
```

```text
域名端口覆盖数量得分
= 平台唯一 FQDN+端口数量
÷ 各参评平台唯一 FQDN+端口并集去重后的总数
× 100
```

```text
关联唯一 IP 数量得分
= 平台关联唯一公网 IP 数量
÷ 各参评平台关联唯一公网 IP 并集去重后的总数
× 100
```

```text
独有有效子域名数量得分
= 平台独有有效子域名数量
÷ 各参评平台独有有效子域名数量之和
× 100
```

```text
DNS发现能力得分
= 有效子域名数量得分 × 40%
+ 域名端口覆盖数量得分 × 25%
+ 关联唯一 IP 数量得分 × 15%
+ 独有有效子域名数量得分 × 20%
```

### 8.3 结果展示

本章发布 DNS发现能力得分。
